# ADR 0002 — 混合检索：按通道类型平衡 + RRF + rerank 主导 + 锚保底

- 状态：accepted（W3, v0.3-prod）
- 日期：2026-09-19

## 背景

W2 用 BGE-M3 稠密 top-k + 类型配额 + 结构化兜底。两类问题召回不好：

- **抽象问法**：“有没有绕过网络限制的尝试”——向量靠近似语义，但真实证据
  （curl 被拦→换 web_fetch/urllib 的事件卡）排不进 top-k；
- **精确命令词**：“chmod/sudo 提权”“node -e fetch npm”——工具名/命令/路径
  是精确词项，稠密向量天然不敏感，而命令词往往只出现在事件卡正文。

同时语料天然不均衡：report_chunk 4191 张，event_card 1219 张，约 3.4:1。

## 决策

检索管线（`hybrid.py`）：

1. **双路召回**：Qdrant 稠密（BGE-M3 / MPS）+ 无依赖 BM25（自实现，shell 词项
   原样保留、中文按 bigram、锚主体命中加权）。
2. **通道内类型平衡**：每路 over-fetch 到 2N，再各取 top 事件卡 N + top 非事件
   卡 N，**然后**才做 RRF。否则约 3.4 倍数量的长 report chunk 会靠词频占满
   RRF top-20，把真实事件卡挤出候选池。
3. **RRF 融合**（k=60）：稠密语义与稀疏精确词等权；意图扩展查询（“绕过”→
   “curl web_fetch 同一 URL 换工具”）以 0.6 权重并入，打通抽象问法。
4. **bge-reranker-v2-m3 重排**融合池 top20。最终选择以 cross-encoder 分数
   **主导**，但加两层最小保底：
   - 精确 payload 锚（如 category=fail-closed）是该意图的事实集合，可占满；
   - 无锚时以融合池最佳 RRF 候选锚定首位（reranker 对长 report/簇文本打分
     不稳定，会把高度相关的事件簇误压下去），并保证 top-k 至少含一张事件卡。

## 踩过的坑（为何不是“一个固定类型配额”）

我们先后试过固定“事件 ≥3、报告 ≤2”和按类型独立 RRF，都会在不同问题间此消彼
长：硬配额会丢掉 reranker 高分的跨类型佐证（绕过序列的事件簇 CL-*），独立
RRF 又丢失跨类型互相增强。最终结论：**让 rerank 决定相关性，只用最小锚点防止
系统性偏差**，而不是用固定配额替模型做排序。

## 结果

`examples/eval_w2_vs_w3.py`（8 问、Recall@5，同一题集跑两条管线）：
mean Recall@5 **0.507（W2）→ 0.647（W3）**。精确命令/绕行类问题提升最大
（node-fetch 0.33→0.67、curl→web_fetch 0.33→1.0、绕过网络 0.14→0.43），
fail-closed 维持 1.0。

## 不选的方案

- 只用稠密：精确词项召回差；只用 BM25：抽象语义差。必须混合。
- Qdrant 原生 sparse 向量：可作为 W4 升级；当前内存 BM25 对 5.5k 文档零运维
  且 tokenizer 可控。
